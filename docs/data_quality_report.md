## What each rule is for

| Rule | Test | Action | Reasoning |
|---|---|---|---|
| 1 | `value < 0` | drop | A concentration cannot be negative. Usually a zero-drift or calibration artefact. |
| 2 | `value == 0` for PM2.5/PM10 | drop | An exact zero is an instrument reporting nothing, not air containing nothing. Gases can legitimately read zero, so the rule is restricted to PM. |
| 3 | `value in (999, 9999, -999)` | drop | Legacy no-data sentinels that pass through as if they were measurements. 999 µg/m³ of PM2.5 is not physically impossible, which is exactly why this rule has to be explicit rather than left to rule 4. |
| 4 | PM2.5 > 1000, PM10 > 2000 µg/m³ | drop | Above any credible ambient reading, including during a severe episode. |
| 5 | identical value ≥ 6 consecutive hours | drop the run | A stuck sensor. This is the most dangerous category because it looks like data: it has a plausible magnitude and it fills the gap that would otherwise be visible. |
| 6 | day built from < 6 hours | **keep, flag** | A sparse day is still information. It is kept with a low `completeness` value, and the frontend greys it out rather than colouring it. |

## Known gaps in the metadata

- **State is not source data.** OpenAQ v3 gives a country and a `locality`; it does not give a state or province. The `state` column is filled from a city→state lookup in `backend/jobs/regions.py`. 0 of 65 stations have no state as a result.
- 0 of 65 stations have no city label.
- **Station siting is not recorded.** A roadside monitor and a background monitor a kilometre apart measure genuinely different air, and nothing in this dataset distinguishes them. City averages mix the two.
- **A station's absence is not information about air.** The map draws a station that has stopped reporting in grey, never in a colour. Distinguishing 'clean' from 'not measured' is the single most important thing this dataset has to get right, and completeness is how it does it.

## Reproducing this

```bash
cd backend
python -m jobs.collect --synthetic --to 2026-08-31 --years 5   # seed=20260904, deterministic
python -m jobs.clean
```

The generator is seeded, so the synthetic path reproduces byte for byte. The API path will not: OpenAQ backfills and revises, so a collection run a month from now legitimately returns different numbers for the same dates. `data/raw/provenance.json` records which mode and which window produced any given lake.
