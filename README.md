# AIRINDEX — India Air Quality Explorer

Five years of Indian air quality, from OpenAQ to a map you can click, with
the data-quality accounting kept in the open. Runs entirely on your own
machine: XAMPP for the database, Flask for the API, Vite + React for the
frontend. No cloud services, no paid APIs, no Docker.

> **Data provenance.** `data/raw/provenance.json` records what produced the
> dataset currently loaded. If it says `"synthetic": true`, the station
> names, cities and coordinates are real CPCB/OpenAQ monitoring sites but
> every concentration value was generated by `backend/jobs/synth.py` —
> because OpenAQ v3 needs an API key. Set `OPENAQ_API_KEY` and re-run
> `collect.py` for real measurements. Every generated artefact says so on
> its face, including `docs/data_quality_report.md`.

## Quick start

Start MySQL from the XAMPP control panel, then:

```bash
# 1. schema
/Applications/XAMPP/xamppfiles/bin/mysql -u root < backend/schema.sql

# 2. backend
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env          # then set OPENAQ_API_KEY if you have one

# 3. data — three commands
.venv/bin/python -m jobs.collect --synthetic --to 2026-08-31 --years 5
.venv/bin/python -m jobs.clean
.venv/bin/python -m jobs.load --truncate
.venv/bin/python -m jobs.publish

# 4. serve
.venv/bin/python wsgi.py       # http://127.0.0.1:5000/api/health
```

With a real API key, step 3's first command becomes:

```bash
.venv/bin/python -m jobs.collect --all --years 5
```

Frontend:

```bash
cd frontend && npm install && npm run dev    # http://localhost:5173
```

## Stack

| Layer | Choice |
|---|---|
| Data source | OpenAQ v3 REST API (`X-API-Key`) |
| Collector | Python, run manually |
| Database | MariaDB 10.4 via XAMPP, `localhost:3306` |
| Backend | Flask, app-factory, raw parameterized SQL via PyMySQL |
| DB access | PyMySQL + `backend/sql/*.sql` — no ORM |
| Analysis | DuckDB over the Parquet lake |
| Frontend | React + Vite + react-leaflet, OpenStreetMap tiles |
| BI | Power BI Desktop over an exported CSV |

## How the data moves

```
OpenAQ v3  ──collect.py──▶  data/raw/       hourly parquet, partitioned by year
                                │
                            clean.py        6 rules, every drop counted
                                ▼
                            data/clean/     daily parquet, partitioned by month
                                │           + docs/data_quality_report.md
                            load.py
                                ▼
                            MariaDB         stations, readings_daily
                                │
                          publish.py
                                ├──▶ frontend/public/snapshot.json   map works with no API
                                └──▶ powerbi/airindex_daily.csv      flat export
```

The collector pulls **hourly** data, not the daily means the API can hand
back directly. Two of the cleaning rules need the hours: a flatline is
defined over consecutive hours, and `n_hours`/`completeness` cannot be
recovered from an average somebody else already took.

## Things this project is deliberate about

**Completeness is load-bearing.** A station that stopped transmitting still
has a "latest" value. Rendering it green would show clean air where there is
no instrument. Bands are withheld below 50% completeness — of the day *and*
of the 30-day window — and the API returns `band_withheld` saying which test
failed, in words the UI shows verbatim.

**Axis order is decided in exactly one place.** MariaDB 10.4 has no
SRID-aware geometry; its `POINT(x, y)` is `(longitude, latitude)`. Get it
backwards and Delhi–Mumbai comes out at 560 km instead of 1148 km, silently.
The two triggers in `schema.sql` are the only code that builds a geometry,
and `backend/tests/test_axis_order.py` fails loudly if the behaviour changes.
This contradicts the usual MySQL 8 advice, where SRID 4326 is latitude-first
— both are true, of different servers. See `docs/methodology.md`.

**The map does not need the backend.** `publish.py` writes a bundled
snapshot; the map renders from it. The API powers nearest-station lookup,
comparison and alerts only. Kill Flask and the map still draws.

**No SQL is built by string concatenation.** Every statement lives in
`backend/sql/*.sql` and is parameterized. The comparison endpoint runs one
indexed query per city rather than assembling an `IN` list.

**Nothing is emailed.** `send_email()` appends to `logs/emails.log` and
prints. One function, so it can be swapped for real delivery later.

## Asia expansion

The collector has no India-specific logic. Changing country is one value:

```bash
.venv/bin/python -m jobs.collect --country TH --all --years 5
```

Run `.venv/bin/python -m jobs.collect --verify-country-agnostic` to list
every place a country is referenced. The one country-specific piece is the
optional city→state lookup in `jobs/regions.py`, which returns `None` for an
unknown country — a missing label, not a broken collector.
